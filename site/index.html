PROBLEM

When an AI agent changes code, who has the final say?

AI coding agents write code and change files at machine speed, without human intervention. That speed is valuable — but not every change should go unchecked. The critical question is: who decides which changes need control?

When an agent applies a change straight to disk, the moment a human decides may come after the change rather than before it. At that point, rollback is costly and slow.

A fast agent does not mean its changes are automatically governed and evidenced. Speed and governance are different things: which change gets applied, who decides, and how that is proven are separate questions.

TANUQ fills that gap as an independent governance layer. It manages the governance step between the agent's proposed file change and its execution — assessing the proposal, requesting human approval for risky changes, applying the approved change, verifying it, and recording every step in the evidence chain.

HOW IT WORKS

Six steps.

Propose → Risk → Approval → Execute → Verify → Evidence. Every step is visible; authority never moves to the next step on its own.

1Proposal

The agent does not write to disk directly; it sends a change proposal to TANUQ. The target file and its content become visible before anything is applied.

2Assessment

Every proposal is classified: acceptable changes can be applied, risky changes wait for your approval.

3Approval

You keep the decision on risky changes. Nothing is applied without your approval.

4Execution

Approved changes are applied atomically. They never leave the approved scope.

5Verification

Compilation and tests run after the apply. If verification fails, the rollback mechanism engages and the outcome is recorded.

6Evidence

Every proposal, approval and outcome is recorded. Later modifications to the record can be detected.

DETERMINISTIC RISK

Risk classification is rule-based and deterministic; the same proposal gets the same decision.

POLICY BINDING

Every proposal is evaluated within policy; behavior outside policy is denied by default.

AUTHORIZATION

Risky changes require explicit human approval before execution; no approval, no apply.

FINGERPRINT-BOUND

Approval is bound by SHA-256 fingerprint to the proposed content; if the content changes, the approval becomes invalid.

SINGLE-USE

Each approval is single-use; the same approval cannot authorize a second execution.

BOUNDED ATTEMPTS

Execution attempts are bounded; uncertain (UNKNOWN) outcomes are never treated as success.

CONTROLLED EXECUTION

Approved changes are applied atomically and never leave the approved scope.

VERIFICATION

Real tests and compilation run after the apply; if verification fails, the rollback mechanism engages and the outcome is recorded.

TAMPER-EVIDENT EVIDENCE

Every proposal, approval and outcome is written to an append-only record.

HASH-CHAIN LINEAGE

Records live in a hash chain; later modifications to history can be detected.

THE DIFFERENCE

Models change.
The governance and evidence layer must not.

Agent intelligence is replaceable. Governance state is not.

The model changes. The provider changes. The tool changes. The governance state TANUQ manages — fingerprint, approval, execution record and evidence chain — stays the same. The core is vendor-blind; decisions bind to the change itself, not to a person or a model.

Validated today: the official Claude Code adapter and the general --stdin-json channel, tested end-to-end with a different model.

FAQ

Before you get started

What is TANUQ?

An independent governance layer between your AI coding agent's proposed file change and its execution. The agent proposes; TANUQ assesses it, requests approval for risky changes, applies, verifies and records evidence.

Which agents does TANUQ support?

Two validated paths: the official Claude Code adapter and the general --stdin-json channel, which is not tied to a specific model (validated end-to-end with a different model). Other agent integrations are not yet validated.

What happens when I change agents?

The core is vendor-blind. Adapters only translate incoming tool events; fingerprint, risk, approval and evidence semantics stay the same. A new agent means a new translation module; the governance core does not change.

Does TANUQ replace my coding agent?

No. The agent writes and proposes; TANUQ governs that proposal. Your agent keeps working — the change flow passes through TANUQ.

How does approval work?

Required for risky changes: single-use, bound to the fingerprint (content), and time-limited (TTL). Nothing is applied without approval.

How is risk determined?

By a deterministic risk engine and policy — rule-based and independent of the proposal source. An LLM recommendation can only raise risk; it can never lower it.

What does verification do?

It runs compilation and real workspace tests after execution. If verification fails, the rollback mechanism engages and the outcome is recorded.

Why does evidence matter?

Every step is kept in an append-only hash chain. If a record is modified later, that can be detected; the evidence chain verifies independently.

How do I install TANUQ?

Python 3.12+ is required. Local install commands are in the Install section; the distribution package is not yet published.

Is TANUQ free?

Yes — TANUQ is free to use. Future pricing has not been decided yet.

How can I get TANUQ?

TANUQ is free to use. Install it from this page — see the Install section. There is no account and no payment.

What are TANUQ's limits?

It is not operating-system-level protection and not network enforcement; it does not sandbox your agent. TANUQ governs the change flow: it makes proposals visible, requests approval, verifies and records them.
